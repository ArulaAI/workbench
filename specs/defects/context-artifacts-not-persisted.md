# Defect: Code-context artifacts do not persist after task completion

Severity: P2
Related Feature: continuous-learning
Tags: observations, context

## Observed Behavior

`code-context.json` files generated by Layer 2 (`lib/context/layer2.py`) during task execution are not reliably available after the pipeline completes. The observation infrastructure (Steps 7-8: context effectiveness and decomposition quality) depends on comparing these files against `git diff` to identify context misses and context waste.

Two factors cause the gap:

1. **Path indirection.** Task JSON has no `feature` field. `layer2.py` falls back from `task_output_base` (which requires feature context) to `context_dir` at `.speed/context/tasks/<id>/context/code-context.json`. The fallback path is global, not feature-scoped, so files from different features can overwrite each other.

2. **No guaranteed persistence.** The worktree for a task is removed after completion (`git_remove_worktree` in `lib/git.sh`). While `code-context.json` is written outside the worktree, its persistence is incidental rather than designed. No pipeline step copies context artifacts to the feature directory, and no contract guarantees the file survives.

## Expected Behavior

After a feature completes, every task's `code-context.json` should be available at a predictable, feature-scoped path (e.g., `.speed/features/<name>/context/code-context-<id>.json`). The observation infrastructure should be able to read these files during extraction without relying on global paths or hoping nothing overwrote them.

## Impact

Without persisted context artifacts, the observation system cannot produce `context_miss` or `context_waste` observations (PRD stories O6). Context tuning, a downstream consumer, has no signal to work with. The RFC documents this as a known drawback and skips Steps 7-8 when files are missing, but the learning gap compounds across features.

## Reproduction Steps

1. Run `speed run` on a multi-task feature
2. After all tasks complete and integrate, check `.speed/context/tasks/<id>/context/code-context.json`
3. Files are either missing or belong to the most recent feature that ran (overwritten)
4. `.speed/features/<name>/` has no copy of context artifacts

## Suggested Fix

After Layer 2 builds the context package, copy `code-context.json` to `${FEATURE_DIR}/context/code-context-${task_id}.json`. A single `cp` in `lib/cmd/run.sh` after the `_context_python` call (around line 640) would be sufficient. The feature directory already persists across pipeline stages.
