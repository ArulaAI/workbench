Planning Plane

Validator support

OWNS cross-spec consistency audit
READS all spec files in specs/
WRITES validation report (JSON)
HANDOFF Architect

Architect planning

OWNS task decomposition, DAG construction, contract generation, file ownership
READS specs, codebase context (CSG), conventions
WRITES .speed/tasks/*.json, contract.json
GATES Product Guardian (pre-plan)
HANDOFF Plan Verifier
VERIFY → REPLAN LOOP

Plan Verifier planning

OWNS adversarial blind verification (no architect reasoning)
READS product spec, task plan only
WRITES verification report, coverage gaps
HANDOFF Task Scheduler · or loop to Architect

PLAN VERIFICATION LOOP

  1. Plan Verifier receives spec + plan (blind)
  2. If coverage gaps found → feeds back to Architect with gap report
  3. Architect re-plans with verifier feedback
  4. Repeat until pass or escalate to human
Execution Plane

Task Scheduler

OWNS DAG traversal, parallel agent spawning, worktree creation, model escalation
READS task DAG, dependency graph, speed.toml
WRITES task status (pending → running), worktrees/
HANDOFF Developer Agent (per task, parallel)
PER-TASK EXECUTION · ISOLATED WORKTREE

Developer Agent support → planning

OWNS single task implementation on isolated git branch
READS task desc, specs, conventions, code context, cross-task context
WRITES code on branch, commits, gate outputs
HANDOFF Quality Gates · or Debugger on failure

Quality Gates

OWNS grounding checks (diff, scope, imports) + quality checks (lint, type, test)
READS git diff, declared files, task scope, lint/test config
WRITES gate results (pass/fail per check)
HANDOFF Reviewer on pass · Developer on fail (retry loop)

FAILURE RECOVERY LOOP

  1. Developer fails → Debugger classifies root cause (syntax, import, type, test, schema, spec_error)
  2. Supervisor selects recovery: retry, retry_escalated (support→planning), replan, reorder, fix_root_cause, skip
  3. Pattern detection: 2+ same error → systemic root cause investigation
  4. >30% tasks failed → halt pipeline, escalate to human
Review & Integration

Reviewer support

OWNS code-to-spec alignment, quality gate inspection, scope check
READS git diff, acceptance criteria, product spec
WRITES review report (approved / change_request with citations)
GATES Product Guardian (post-review)
HANDOFF Coherence Checker · or Developer for changes

Coherence Checker planning

OWNS cross-task interface, schema, and naming consistency; contract satisfaction
READS all task branch diffs, contract.json, product spec
WRITES coherence report (raw JSON)
HANDOFF Integrator · or Supervisor on failure

Integrator support

OWNS branch merging (dependency order), conflict resolution, regression tests
READS completed branches, test config, merge state
WRITES merged commits on main (--no-ff)
GATES contract verification (non-LLM) · regression suite · Product Guardian (post-integration)

Debugger support

OWNS failure classification, root cause analysis
READS error logs, diff, gate results
WRITES diagnostic report
HANDOFF Supervisor

Supervisor support

OWNS recovery strategy, pattern detection, halt decisions
READS task state, failure history
ACTIONS retry · escalate · replan · reorder · skip · halt
Cross-Cutting

Product Guardian support

OWNS product vision preservation, scope creep detection, anti-goal enforcement
READS product vision (specs/product/overview.md), scope learnings
WRITES alignment report (aligned / flagged / rejected)
GATES pre-plan · post-review · post-integration

Context Assembly (CSG)

OWNS dynamic context building: code symbols, spec sections, cross-task interfaces
READS codebase (AST), all specs, task scope declarations
WRITES assembled context → injected into Architect, Developer, Coherence Checker prompts

Learning System

OWNS convention extraction, synthesis, human corrections
READS codebase patterns (naming, imports, testing), human feedback
WRITES convention guides → injected into Developer + Reviewer context
Pipeline State · .speed/ directory

.speed/tasks/

task dag

JSON per task; status machine (pending → running → done → approved); dependency edges; file ownership

contract.json

data contract

machine-verifiable entities: database tables, files, functions; verified non-LLM at integration

.speed/worktrees/

git isolation

one worktree per task; isolated branches; symlinked node_modules/.venv for speed

specs/

input specs

product, tech, design, defect specs; source of truth for all agent reasoning

.speed/logs/

observability

per-agent logs, gate results, timing data; category-split files

.speed/defects/

defect state

filed → triaged → fixing → resolved; severity, triage output, blast radius

.speed/shared/

multi-player

event log (JSONL), roster, proposals, shared knowledge; team coordination

validate → plan → verify → run (parallel per task) → review → coherence → integrate  ·  Product Guardian gates at pre-plan, post-review, and post-integration  ·  Failure recovery via Debugger → Supervisor at any execution phase  ·  Contract verification (non-LLM bash) at integration
